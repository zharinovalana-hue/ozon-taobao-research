# Методика и происхождение параметров

Модель сохраняет формулы исходного листа «Расчёт». Пользователь относится к одной из четырёх когорт и одному из четырёх дневных состояний: только Корзина, только Избранное, оба раздела, ни один. Состояния взаимоисключающие. Покупатель с несколькими заказами учитывается один раз.

Для каждого состояния:

```
CR_state = CR_cohort × weight_state / SUM(state_share × weight_state)
unique_target = eC × visitC + eF × visitF − eCF × visitC × visitF
uplift_retention = (1 − behavioral_penalty) × (1 − product_penalty)
buyers1 = buyers0 × (1 − lossC × visitC) × (1 − lossF × visitF)
          × (1 + 0.10 × unique_target × uplift_retention)
```

Модель сравнивает каждую H с одной базой. Эффекты разных H не складываются. H6 выбирает одну реализацию. Три одинаковых результата H6 вызваны одинаковыми входами, а не доказанной эквивалентностью решений.

## Что взято из кейса

Дневные охваты C/F 65%/13%, месячные 91%/20%; 60–80% посетителей C имеют товары F; разрывы CR относительно S1 равны 0/−9/−18/−9 п.п.; защитные метрики не должны снижаться. Все числа кейса синтетические. Разрывы интерпретируются как дневные пользовательские CR для целей модели; исходный PDF не раскрывает точную атрибуцию и период. MAU не используется как знаменатель дневного эффекта.

Среднее и медиана размеров списков, данные платформ и результаты прошлых экспериментов сохранены. Порог H1 40+ SKU не выводится из порога cart_count≥14 Taobao. Внешний сценарий переносит только форму четырёх долей; охват H1 внутри «большой» когорты остаётся допущением.

## Что стало фактическим внешним входом

В предоставленном агрегате Taobao подтверждены 987 994 пользователя и четыре когорты при C≥14/F≥9: 90 851 / 11 747 / 98 635 / 786 761. Доли вычисляются из этих целых чисел, а не из округлённых процентов. Тот же агрегат определяет пороги P75/P95/P99 и альтернативные доли. Повторы user_id и пропуски отсутствуют.

Флаг purchased отмечает любой buy в окне. Добавление и покупка одного товара не связаны; порядок действий не проверяется. Purchase rate за девять дней не переносится в дневную CR и не делится на девять. В Taobao S2/S3 покупают чаще S1; порядок CR из учебного кейса отдельно сохраняется. Сегментация и покупки в одном окне создают возможную обратную причинность/отбор по активности.

Внешний сценарий №4 использует Taobao-доли и прокси наличия F из факта добавления, без принуждения к Ozon-условию владения. Он явно маркируется как внешний и не объявляется прошедшим ограничения Ozon. Дневные CR в нём всё ещё условны, а не измерены на Taobao. При обновлении данных нецелый интерполированный процентиль округляется вверх для условия count≥percentile; совпадения на пороге сохраняются.

## Калибровка и шкалы

В сценариях с проверкой условий Ozon сохраняется сценарный совокупный уровень владения F 70%, лежащий внутри диапазона кейса. При Taobao P90 доля «владельцев» в малом F равна `(0.70 − S1 − S2)/(S3 + S4) = 66.523657%`. Это расчёт согласованности, не новая оценка реального владения.

CR0=20,1% сохраняется в исходном контроле №2 и отдельном Taobao-контроле №5. Рабочий базовый сценарий использует **15%**, осторожный 12%, благоприятный 18%; дополнительно проверены 10%, 12%, 18%, 20,1%. Все уровни являются допущениями. CR S1 выводится из глобального якоря и взвешенных разрывов. Слишком низкий якорь, дающий отрицательную CR S3, отклоняется.

Масштаб рабочих сценариев: DAU 44 млн и MAU 84 млн в марте 2026 по Ozon IR. Доли кейса на этом масштабе являются условной экстраполяцией: DAU C 28,6 млн, F 5,72 млн; MAU C 76,44 млн, F 16,8 млн. Исходные контроли остаются нормированными на DAU 100 000 и MAU 400 000.

807,7 млн заказов / 90 дней / мартовский DAU 44 млн = 0,20396 заказа на условный DAU-день. Деление на CR15% даёт около 1,36 заказа на покупателя-день. Это диагностический ориентир, требующий предположения о неизменном среднем DAU и совпадении охвата аудитории/продуктов. Он не измеряет долю уникальных покупателей и не используется как жёсткая граница. III квартал и мартовский DAU не смешиваются.

Выручка и GMV различаются. Реальная выручка на уникального покупателя за день неизвестна. В старых контролях сохранены 1 000 условных единиц на покупателя, в новых используется единичный индекс. Проверяется направление изменения ARPU и индекс к базе 100; рублёвого прогноза нет. Сохранённая формула дохода применяет изменение дохода пропорционально целевой доле состояния; индивидуальная реакция покупателей не идентифицирована.

## Что остаётся допущением

| Параметр | База | Что проверяется |
|---|---|---|
| Uplift | +10% относительной CR цели | Общее условие; 25%/25% штрафов оставляет +5,625% внутри полностью охваченной цели |
| Охваты H | Сохранена прежняя матрица | Множители 0,5/0,6/1/1,25/1,5, структурные нули сохранены |
| Визиты по когортам | C65%/F13% одинаково во всех когортах | Общий итог известен, распределение по когортам неизвестно |
| Пересечение визитов | P(C-визит при F-визите)=80% | 0/50/80/100%; это не 60–80% владения из кейса |
| Пересечение целей | H2/H4 10% среди двойных посетителей | Ограничения Фреше и изменение масштаба охвата |
| Склонность к покупке по состояниям | 1,5 / 0,2 / 1 / 0,3 | Дополнительный стресс 1,2 / 0,4 / 1 / 0,5; платформенная смесь не известна |
| Штрафы пользы | 25%/25% | 0/25/50/100%; 100% означает отсутствие полезного эффекта |
| Потери базовой CR | 0 | Осторожный C−0,1%, F−0,2%; отдельные C−0,5%, F−3%; совместный C−0,5%, F−1%, все относительно |
| Доход на покупателя | Без изменения | Осторожный −0,5%, отдельный −10%, совместный −2%, применяются в целевой доле |

Потери C/F в исходной формуле затрагивают всех посетителей соответствующего раздела в когорте, а не только целевую долю. Для F-функций потеря C является стрессом возможного косвенного ущерба, не утверждением о неизбежной причинной связи. Штрафы, потери и сетка сценариев не являются оценёнными вероятностями. Частота провала на выбранной сетке не является вероятностью провала в реальном эксперименте.

Отдельной вероятности восстановления заказа в модели нет: прирост задан относительно исходных покупателей. Добавление такого коэффициента потребовало бы явной модели непокупателей, времени и атрибуции. Опросные причины отказа и конверсии рассылок не заменяют эту вероятность.

## Воспроизводимость Excel

Полная матрица весов по четырём когортам каждого сценария находится в правой части «Входы H», столбцы N:Q. Значения X:AA на «Сценариях» показывают справочно веса S1 и ссылаются на эту матрицу. Прямое редактирование справочных формул не является изменением расчётных весов.

Авторская доработка выполнена через Artifact Tool с импортом существующего XLSX. Публичный Python-пересчёт изменяет только нужные XML-части существующего файла, сохраняя формулы, стили, проверки ввода и диаграмму. Поддерживаемые функции: IF, CHOOSE, AND, OR, NOT, COUNT, SUM, SUMPRODUCT, MIN, MAX, ABS, ISNUMBER, арифметика, сравнения и ссылки/диапазоны. Неподдерживаемые функции, неверные данные и циклы вызывают ошибку.

Источником воспроизводимого запуска являются JSON/код сценариев. Ручное изменение Excel является локальным экспериментом и помечает сохранённые сравнения устаревшими. Для закрепления решения обновите JSON/сценарии и запустите Python. Изменение схемы/числа сценариев требует явного обновления структуры шаблона и не обрезается молча.
