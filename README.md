# Ozon: сценарная модель и отдельный анализ Taobao

Существующая модель исправлена: **поток добавлений Taobao больше не используется как распределение остатков SKU Ozon или охват H1**. Сохранены исходная Excel-модель, формулы «Расчёт», первые три контрольных сценария и первоначальная UX ICE.

- [Выводы, таблицы и порог H1/H4](docs/findings.md).

- [Методика](docs/methodology.md), [источники](docs/sources.md), [Colab: события Taobao](notebooks/taobao_reproducible.ipynb).

**Это сценарный расчёт, не результаты A/B-тестов.** Все гипотезы получают +10% относительной CR целевой группы до охвата и рисков. Сетка сценариев не задаёт вероятностей.

Среднее 60, медиана 24 и максимум 300 SKU допускают широкий диапазон доли 40+: необходимые границы около **10,92–50%**. Построены пять точных распределений: 11/20/30/40/49%; они не являются измерениями. 30% выбрано для иллюстрации, а не оценено по данным.

При прежней условной потребности H1=40% H4 выше H1 во всех пяти распределениях; H1 требует 82,40% больших Корзин при прочих базовых параметрах. При потребности H1=80% порог снижается до 45,76%, при 100% — до 38,06%. H4 — условный лидер: при 11% больших Корзин немного выше H2. Эти пороги зависят от переноса stock-распределения на аудиторию модели, связи C/F, посещаемости и охватов H1/H4.

## Excel

На листе «Параметры», B3, выберите сценарий 1–35. «Итоги» пересчитываются формулами. №2 воспроизводит прежний контроль, №6 — новая иллюстративная база. Добавлены «Размеры Корзин» и «Порог H1 H4»; Taobao сохранён отдельным листом.

«Сравнение» и «Порог H1 H4» содержат сохранённые срезы. При изменении входов предупреждают об устаревании; для полного обновления запустите Python. Жёлтые поля позволяют локальные эксперименты. H1: AB на «Сценариях» — потребность среди уже больших Корзин; AC — множитель охвата H4. Матрица посещаемости по когортам находится на «Входы H», R:S, веса — N:Q. Для воспроизводимости переносите выбранные изменения в код/JSON.

## Пересчёт без сырых данных

Требуется Python3.11+; CI использует3.12. Скачайте весь репозиторий, включая models/.

```bash
python -m pip install -r requirements.txt
python scripts/run.py
python scripts/write_reports.py
python -m unittest discover -s tests -v
```

Для отдельного файла:

```bash
python scripts/run.py --output Ozon_recalculated.xlsx
```

Команда обновляет существующий Excel, CSV/JSON, гистограммы и таблицу порогов. Источник коэффициентов — data/model_inputs.json; сценариев — src/ozon_model.py; конструкции распределений — src/cart_stock.py. data/scenarios.json автоматически формируется и не является ручным входом. Полный архив Taobao не нужен.

## Отдельный анализ Taobao

Если агрегат уже есть:

```bash
python scripts/run.py --users /path/to/taobao_users.csv
```

Это обновит события Taobao, не когорты Ozon. CSV содержит user_id,cart_count,fav_count,purchased, одну строку на пользователя. В GitHub публикуются только агрегаты. Colab по умолчанию читает существующий файл /content/drive/MyDrive/taobao_users.csv; полный архив используется только при отсутствии агрегата или REBUILD=True. Повторно загружать исходный архив не требуется. Colab из этой среды не запускался.

## Проверки и пределы

Добавлено отдельное [расширение Монте-Карло](docs/monte_carlo_methodology.md): 100 000 допустимых миров в каждом из трёх профилей, индивидуальные эффекты H, ранговая чувствительность Спирмена, попарные сравнения и сходимость. [Распределения входов](data/monte_carlo_assumptions.json) являются экспертными сценарными допущениями. [Сводки](results/monte_carlo/profiles.json) и [графики для презентации](outputs/monte_carlo/presentation-notes.md) не подменяют A/B-тест и доверительные интервалы реальных эффектов. Исходный Excel не меняется при запуске расширения.

```bash
python -m pip install -r requirements-plots.txt
python scripts/run_monte_carlo.py
python scripts/plot_monte_carlo.py
```

Сохранены 45 исходных проверок Excel; 35×8 результатов сверены с Python. Проверяются исходные формулы, кеши, уникальная аудитория, пересечения, нулевые/отрицательные эффекты, моменты распределений, stock/flow, пороги и воспроизводимый refresh. Настроен [GitHub Actions](.github/workflows/verify.yml). Настольный Excel не запускался.

Refresh проверяет совпадение всех сценариев перед сохранением. Для контролей 1–3 H1 использует отдельные охваты S2/S3 из JSON; для остальных сценариев — условную потребность AB. Изменение разрывов CR обновляет якоря, границы поиска порога и проверку допустимости Excel. Числа порогов и выводы о лидерах в отчёте формируются из текущих результатов; отсутствие пересечения и равенство эффектов выводятся отдельно.

20,1% — контроль, не факт Ozon. DAU44 млн/MAU84 млн — публичный масштаб марта2026; заказы не заменяют уникальных покупателей. ARPU — условный индекс, не прогноз рублей. Реальные охваты потребностей, связь размеров C/F, состав по платформам, причинный uplift и ущерб остаются неизвестными. H6.1–H6.3 не складываются. UX ICE не пересчитывается.
